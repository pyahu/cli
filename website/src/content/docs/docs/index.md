The Pyahu CLI is the local entry point for the **Pyahu Platform**: a faithful subset
of the real experience, running on your machine. It spins up a development stack on
k3d/k3s using Kubernetes resources generated by the CLI itself, without you having to write
manifests, `kubectl`, or `helm`.

It is **real Kubernetes**, with Traefik, PersistentVolumes, ConfigMaps, and Secrets. The CLI
does not hide k8s from the developer; it makes provisioning and operation easier, and the cluster stays
yours to inspect (`pyahu kubeconfig`) whenever you want.

## Quick install

```bash
curl -fsSL https://cli.pyahu.io/install.sh | sh
```

Or with mise, which pins the version in the repository and keeps the whole team on it:

```bash
mise use --pin "github:pyahu/cli@latest"
```

Other methods (Pyahu toolchain, `go install`, manual download) and the prerequisites are in
[Installation](/docs/installation).

## First cluster

```bash
pyahu init --preset platform   # creates pyahu.yaml
pyahu doctor                   # validates Docker/Podman, k3d and local ports
pyahu up                       # creates the cluster and applies the services
```

When it finishes, `pyahu up` prints the cluster, the namespace, the kubeconfig path, and the
connection variables ready to paste.

:::tip
Run the commands in your project directory. The CLI looks for the `pyahu.yaml` from the current
directory upward, so any subfolder of the project sees the same stack.
:::

## Services in the `platform` preset

| Service | Local endpoint |
| --- | --- |
| PostgreSQL | `localhost:5432` |
| PostgreSQL (read replicas) | `localhost:5433` when `readReplicas > 0` |
| ZITADEL | `https://zitadel.localhost` |
| RabbitMQ | `localhost:5672` |
| RabbitMQ Management | `https://rabbitmq.localhost` |
| Redis (Valkey) | `localhost:6379` |
| Kafka | `localhost:9092` |
| Kafka Connect | `http://localhost:8083` |
| Debezium | configured via Kafka Connect |
| Kafka UI | `https://kafka-ui.localhost` |

The HTTP UIs (ZITADEL, RabbitMQ, Kafka UI) go through Traefik on 80/443 with
`*.localhost` hostnames and the local certificate. The TCP services (PostgreSQL,
Kafka, RabbitMQ AMQP, Redis) and the Kafka Connect REST endpoint keep dedicated ports.

The `minimal` preset spins up only PostgreSQL. See [Configuration](/docs/configuration) to
adjust services, ports, and credentials.

## Connect your apps

```bash
# prints connection variables (shell, dotenv, or JSON)
pyahu env
eval "$(pyahu env)"
```

To see everything that is running and its endpoints:

```bash
pyahu services
pyahu describe postgres
```

The full reference for each command is in [Commands](/docs/commands).

## Local TLS

When ZITADEL is enabled, the CLI issues a local certificate for `*.localhost`.
Trust the CA on the host once to use `https://zitadel.localhost` without warnings:

```bash
pyahu certs trust
```

Details in [Local certificates](/docs/certificates).

## Cleanup

```bash
pyahu down                 # removes the k3d cluster
pyahu down --keep-cluster  # keeps the cluster and removes only the stack namespace
```

If you change ports after the cluster already exists, recreate it. k3d pins the port
mappings at creation time:

```bash
pyahu down
pyahu up
```
